# 面向编程初学者的 RL 工程课设计

## 1. 课程定位

这不是一份从数学推导开始的强化学习理论教材，而是一套以 UIKA 四足机器人和 HimLoco 为案例的工程实验课。理论概念由授课者提供的视频与阅读材料承担；本文档负责把概念落实到 Ubuntu 操作、Isaac Lab 配置、训练实验、日志分析和故障排查中。

课程的最终成果是：读者能够在 `himloco_lab` 中定位并修改 command、observation、action、reward、termination、event 和 curriculum，完成受控的对照训练，并依据 TensorBoard 曲线和机器人行为给出初步诊断。

## 2. 目标读者与边界

目标读者：

- 掌握基础 Python 或 C 语言语法；
- 不要求会 Ubuntu、Git、conda 或常用终端命令；
- 不要求学过强化学习、机器人学或 Isaac Lab；
- 使用 Ubuntu 22.04 和 NVIDIA 独立显卡，显卡型号不统一。

课程内负责：

- 完成任务所需的最小 Ubuntu、终端、Git 和 conda 知识；
- 固定并验证可复现的软件版本；
- 解释本仓库的训练数据流和主要配置接口；
- 设计可在不同显卡上缩放的实验；
- 教会读者保存证据、比较实验和排查常见问题。

课程外内容：

- PPO、优势函数和对比学习的完整数学推导；
- Linux 系统管理通识；
- CUDA 编程；
- 完整 Sim2Real 部署。部署只作为后续方向说明，不作为本阶段考核目标。

## 3. 教学组织原则

采用“行为驱动的模块化实验”为主线：

1. 从一个可观察的机器人行为问题开始；
2. 说明本节与哪项 RL 概念有关；
3. 找到论文中的设计动机；
4. 沿本地代码追踪实现；
5. 只改变一个主要变量；
6. 运行基线组与实验组；
7. 用曲线、配置快照和回放行为形成结论。

章节顺序不照搬论文，也不按 API 名称堆砌。Isaac Lab 的 manager 体系作为知识骨架，HimLoco 论文作为设计旁注，一次完整的 UIKA 策略改造作为贯穿项目。

## 4. 课程结构

课程按 11 个模块组织（第 0 课至第 10 课），可压缩为 8 课时，也可将奖励和训练诊断拆分后扩展至 12 课时。

| 模块 | 工程问题 | 主要产出 |
|---|---|---|
| 0. 环境与工具 | 如何证明电脑真的能运行课程项目？ | 环境验收记录 |
| 1. 第一次运行 | 训练命令启动后发生了什么？ | 一次冒烟训练与日志目录 |
| 2. RL 闭环 | 一步仿真中数据怎样流动？ | 数据流图与术语映射 |
| 3. 任务与场景 | `--task` 如何找到 UIKA 和地形？ | 任务注册追踪记录 |
| 4. Observation | 策略看到了什么，哪些信息只给 critic？ | 观测维度表与一次消融 |
| 5. Action | 网络输出怎样变成 12 个关节目标？ | 动作缩放实验 |
| 6. Command | “向前走”如何进入训练任务？ | 指令范围实验 |
| 7. Reward | 为什么机器人会走成现在的样子？ | 单变量奖励对照实验 |
| 8. Reset 与随机化 | 机器人何时重来，为什么每次环境不同？ | 终止/随机化检查表 |
| 9. HimLoco 与训练诊断 | 历史观测、HIM、PPO 和日志如何连接？ | 论文—代码映射与诊断报告 |
| 10. 综合项目 | 如何有证据地改进一个具体行为？ | 可复现实验报告 |

## 5. 每章固定模板

每个实验章节使用相同结构，降低初学者的认知负担：

1. **本节问题**：一句话描述要解决的行为问题。
2. **完成标准**：列出可验证结果，而不是“理解某概念”。
3. **课前材料**：指向课程主页上对应的视频或理论文档。
4. **最少术语**：只解释完成实验必需的词。
5. **代码地图**：给出入口文件、配置文件和实现文件。
6. **先预测**：要求学生在运行前写下预期。
7. **基线实验**：不改代码，记录当前结果。
8. **单变量实验**：一次只改变一个主要因素。
9. **证据记录**：保存命令、commit、配置、seed、曲线和回放。
10. **解释结果**：区分现象、证据和推断。
11. **故障排查**：按“现象 → 检查 → 原因 → 处理”组织。
12. **检查题**：以定位代码和解释实验为主，不考机械背诵。

## 6. 论文与代码的关系

课程使用 ICLR 2024 论文 *Hybrid Internal Model: Learning Agile Legged Locomotion with Simulated Robot Response*。论文是设计依据，本仓库是基于 Isaac Lab 的工程实现，两者不得描述成逐行一致的复现。

主要映射如下：

| 论文概念 | 本仓库入口 | 教学重点 |
|---|---|---|
| partial observation | `ObservationsCfg.PolicyCfg` | 实机可获得的本体感知与指令 |
| privileged information | `ObservationsCfg.CriticCfg` | actor 与 critic 的信息不对称 |
| action as joint-position bias | `ActionsCfg` | 默认姿态、缩放和关节顺序 |
| historical observations | `HimlocoVecEnvWrapper` | 历史帧如何堆叠及其实际长度 |
| explicit velocity + implicit latent | `HIMEstimator` | 3 维速度与 16 维归一化隐变量 |
| HIO | `HIMEstimator.update()` | 速度监督、prototype 和 swap loss |
| PPO | `HIMPPO.update()` | estimator 更新与策略更新的关系 |
| dynamics randomization | `EventCfg` | 摩擦、质量、质心、执行器和扰动 |
| terrain curriculum | `CurriculumCfg` | 难度如何随表现调整 |

课程必须显式指出实现差异。例如，论文默认历史长度 `H=5`，而本仓库 wrapper 将 `history_length=5` 解释为“当前帧 + 5 个过去帧”，实际传入 estimator 的是 6 帧。这个差异应作为“不要只看变量名，要追踪张量”的工程案例。

## 7. 不同 GPU 的运行策略

显卡型号不统一，因此教程不按型号写死训练时间，也不保证所有机器使用相同并行环境数。

采用逐级探测：

- 冒烟档：`--num_envs 16 --max_iterations 1`，验证链路；
- 调试档：从 `--num_envs 64` 开始，用于 GUI 检查或短实验；
- 教学档：逐步尝试 256、512、1024 个环境，以显存稳定和迭代速度为准；
- 完整档：配置默认 4096 个环境，仅在机器承受且需要正式结果时使用。

如出现 OOM，先减少 `num_envs`；如样本量过少导致训练不稳定，不能把小规模短训练与完整训练直接比较，应增加迭代数或只将其用于功能验证。

## 8. 实验记录与评估

每次实验至少记录：

- 实验问题和预测；
- Git commit 与未提交改动；
- 完整启动命令；
- task、seed、`num_envs`、迭代数；
- 实际生效的 `env.yaml` 和 `agent.yaml`；
- 关键 TensorBoard 曲线；
- checkpoint 与回放观察；
- 结论、局限和下一步。

最终项目采用四项评价：

1. **可复现性**：别人能否依据记录重复实验；
2. **变量控制**：基线组与实验组是否只改变目标因素；
3. **证据质量**：结论是否同时参考曲线和行为；
4. **工程解释**：能否沿代码说明改动如何影响训练闭环。

## 9. 文档与支持边界

环境故障分为四层：

1. 驱动/硬件层：`nvidia-smi`、磁盘、内存；
2. Python 环境层：conda 环境、解释器、包版本；
3. Isaac Sim/Isaac Lab 层：应用启动、扩展和任务注册；
4. 项目/训练层：配置、张量维度、NaN、OOM、策略行为。

学生必须先判断故障层级，再使用对应排查表。课程只支持冻结的软件栈；升级到最新 Isaac Sim/Isaac Lab 是独立迁移任务，不应混入入门实验。

## 10. 验收标准

完成课程后，学生应能独立完成以下操作：

- 在新终端中激活正确环境并确认 Python、Isaac Sim 和 GPU 状态；
- 解释训练入口如何解析 task 并创建 UIKA 环境；
- 找出 policy/critic observation、action、command 和 reward 配置；
- 计算 UIKA policy 单帧 observation 的组成；
- 解释动作缩放、默认关节角和 PD 控制之间的关系；
- 修改一项 command 或 reward 并运行带命名的对照实验；
- 从日志中找到实际配置、checkpoint 和 TensorBoard 数据；
- 区分“程序能跑”“回报上升”和“行为满足目标”这三种不同结论；
- 对 OOM、任务未注册、包导入失败和 NaN 做第一轮定位；
- 提交一份包含预测、证据、结论与局限的实验报告。
