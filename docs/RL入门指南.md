## 0. 概述

本项目使用强化学习方法训练四足机器人（机器狗）的运动控制策略，使其能够行走、奔跑及通过复杂地形。

整体流程如下：

1. 在物理仿真器中构建虚拟机器人及虚拟环境；
2. 以神经网络作为机器人的控制策略，根据当前状态输出关节控制指令；
3. 通过强化学习算法，在仿真环境中进行大量试错训练，逐步优化控制策略；
4. 将训练完成的策略部署到真实机器人上（Sim2Real）。

该流程涉及四个层面的知识，本文据此组织：

| 层面 | 涉及内容 | 作用 |
|---|---|---|
| 基础环境 | Ubuntu、Conda、GPU、Git | 开发与运行的软硬件基础 |
| 神经网络 | 神经网络、PyTorch | 控制策略的载体与实现工具 |
| 强化学习 | 强化学习原理、PPO | 策略的训练方法 |
| 仿真生态 | Isaac Sim/Lab、MuJoCo 等 | 训练所依赖的虚拟环境 |

### 1.4 GPU、CUDA 与显卡

CPU 核心数量较少，适合顺序执行复杂任务；GPU（图形处理器，即显卡）核心数量众多，适合大规模并行的简单运算。神经网络训练的核心是大量重复的矩阵运算，与 GPU 的并行能力高度契合，因此深度学习训练通常依赖 NVIDIA 显卡。

- **CUDA**：NVIDIA 提供的并行计算平台与编程接口，使程序能够调用 GPU 进行计算。PyTorch、Isaac Sim 等工具的底层加速均依赖于此。

## 2. 神经网络与深度学习

### 2.1 神经网络

神经网络本质上是一个参数化的函数：接收一组数值输入，经过多层运算后产生一组数值输出。其内部包含大量可调参数（称为**权重**），函数的具体行为由这些参数的取值决定。

在本项目中：

- **输入**：机器人当前状态，包括身体姿态、各关节角度与角速度、目标速度指令等；
- **输出**：各关节下一步的目标角度（本项目机器人有 12 个关节）。

由多个隐藏层构成的神经网络称为**深度神经网络**，相应的方法称为**深度学习（Deep Learning）**。本项目策略网络的隐藏层规模为 `[512, 256, 128]`。

> 参考链接：
> - 3Blue1Brown 神经网络系列：
> - 神经网络基础：

### 2.2 训练过程

神经网络通过调整权重来"学习"，基本机制如下：

1. **前向传播**：输入经网络计算得到输出（预测值）；
2. **损失计算**：以损失函数（Loss）衡量预测值与目标之间的差距；
3. **反向传播与梯度下降**：根据损失计算各权重的梯度（即调整方向），并沿使损失减小的方向更新权重。

上述过程反复迭代，使损失逐步下降，网络性能逐步提升。

需要注意，上述描述对应**监督学习**（存在明确的目标输出）。机器人运动控制问题不存在预先给定的"正确动作"，因此采用强化学习（见第 3 节），但底层的参数更新机制相同。

> 参考链接：
> - 反向传播与梯度下降：

### 2.3 PyTorch

PyTorch 是由 Meta 开源的深度学习框架，提供以下能力：

- 以简洁的代码构建神经网络；
- 自动计算反向传播所需的梯度（自动微分）；

另一主流框架为 Google 的 TensorFlow。目前学术界及本项目所用工具链以 PyTorch 为主。本项目使用的强化学习库（rsl_rl）基于 PyTorch 实现。

## 3. 强化学习

### 3.1 机器学习的三种范式

机器学习按学习方式可分为三类：

| 范式 | 学习方式 |
|---|---|
| 监督学习 | 基于带标注的数据（输入与目标输出）学习两者间的映射 |
| 无监督学习 | 仅基于无标注数据，自动发现数据中的结构与规律 |
| 强化学习（RL） | 无预定义答案，通过与环境交互、依据奖励反馈反复试错来优化行为 |

机器人运动控制不存在标准答案，但行为优劣可量化评估，因此适用强化学习。

### 3.2 强化学习的基本要素

强化学习包含以下核心概念，以机器人控制为例：

- **智能体（Agent）**：进行决策的主体，此处为机器人的控制策略（神经网络）。
- **环境（Environment）**：智能体所处的外部系统，此处为仿真器中的虚拟地形与机器人本体。
- **状态 / 观测（State / Observation）**：智能体所获取的环境信息，如身体姿态、关节状态、速度指令等。
- **动作（Action）**：智能体的决策输出，此处为 12 个关节的目标角度。
- **奖励（Reward）**：环境对智能体行为给出的反馈分值。行走稳定、跟随指令速度等行为获得正奖励；摔倒、异常抖动、非预期接触等行为受到惩罚。

交互流程为：观测 → 智能体输出动作 → 环境执行并更新 → 返回奖励与新观测 → 循环。强化学习的目标是学习使长期累积奖励最大化的策略。

> 奖励函数的设计在很大程度上决定了最终策略的行为表现。本项目环境配置文件 `velocity_env_cfg.py` 中的 `RewardsCfg` 即为奖励项的定义，是策略调优的关键部分。

### 3.3 策略、价值与 PPO

进一步的相关概念：

- **策略（Policy）**：由状态映射到动作的函数（即神经网络本体），是训练得到的最终产物。
- **价值（Value）**：评估当前状态优劣的函数，用于辅助策略训练。
- **Actor-Critic**：将策略（Actor）与价值（Critic）结合的经典架构。
- **PPO（Proximal Policy Optimization，近端策略优化）**：目前机器人控制领域应用最广泛的强化学习算法之一，训练过程相对稳定。本项目即采用 PPO，相关参数（如 `clip_param`、`entropy_coef`）见 `rsl_rl_ppo_cfg.py` 与 `himloco_rsl_rl_cfg.py`。
- **on-policy / off-policy**：两类强化学习算法的区分方式，PPO 属于 on-policy。入门阶段了解该区分即可。

入门阶段无需掌握 PPO 的数学推导，理解其作为成熟训练算法被直接使用、并通过调整其超参数与奖励函数进行实验即可。

> 参考链接：
> - 强化学习入门（EasyRL / David Silver 课程等）：
> - PPO 算法讲解：

### 3.4 强化学习与机器人控制

机器人运动控制适合采用强化学习，原因如下：

- 不存在可供监督学习使用的标准答案；
- 行为的优劣（如稳定性、速度跟随精度）易于量化为奖励；
- 仿真器支持安全、高速的大量试错，弥补了真机训练的代价过高问题。

## 4. 机器人仿真生态

### 4.1 仿真训练的必要性

强化学习需要大量的交互试错。在真实机器人上直接训练存在以下问题：

- 硬件损耗与维护成本高；
- 现实世界无法加速，训练周期过长；
- 试错过程存在安全风险。

因此，训练在遵循物理规律（重力、摩擦、碰撞等）的虚拟环境中进行，该环境由**物理仿真器（Physics Simulator）**提供。

### 4.2 主流物理仿真器

常见的物理仿真器及其定位：

| 名称 | 开发方 | 定位与特点 |
|---|---|---|
| MuJoCo | 原 DeepMind（已开源） | 物理精确、轻量，长期作为学术界强化学习研究的主要工具 |
| Gazebo | 开源（ROS 生态） | 偏向机器人工程与系统集成测试，常与 ROS 配合，不擅长大规模并行训练 |
| PyBullet | 开源 | 轻量、易用，常用于入门与教学 |
| Isaac Sim / Isaac Lab | NVIDIA | 本项目所用工具，支持 GPU 大规模并行仿真，专为大规模强化学习训练优化 |

各仿真器各有侧重：Gazebo 偏工程测试，MuJoCo 与 PyBullet 偏学术研究，Isaac 系列偏 GPU 大规模训练。本项目因训练规模与速度需求选用 Isaac 系列。

> 参考链接：

### 4.3 Isaac Gym、Isaac Sim 与 Isaac Lab

这三者均为 NVIDIA 的机器人仿真工具，按发展时间线区分如下：

1. **Isaac Gym**：NVIDIA 早期的 GPU 并行强化学习仿真器，开创了在 GPU 上并行模拟大量环境的方式，早期诸多四足/人形机器人研究（如 legged_gym）基于此。目前已停止更新。
2. **Isaac Sim**：NVIDIA 新一代综合性机器人仿真平台，渲染逼真、功能完整，是当前的核心仿真引擎，但偏底层，直接用于编写强化学习训练代码较为繁琐。
3. **Isaac Lab**：构建于 Isaac Sim 之上的框架，专为强化学习训练设计，封装了场景构建、观测/动作/奖励定义、训练流程等功能，是 Isaac Gym 的后继方案。

三者关系：本项目代码基于 Isaac Lab 开发，运行于 Isaac Sim 引擎之上，底层调用 GPU/CUDA。`CLAUDE.md` 中"适配 IsaacLab 2.3.2 & IsaacSim 5.1.0"即指此版本组合。

### 4.4 ROS

ROS（Robot Operating System，机器人操作系统）并非传统意义上的操作系统，而是一套用于机器人各功能模块之间通信的中间件与工具集合，负责在传感器、控制器、决策模块之间传递数据。

需要明确的是：

- 训练阶段通常不涉及 ROS，环境交互由仿真器直接提供；
- 在真实机器人部署阶段，ROS（或类似通信框架）常用于连接传感器、控制策略与执行器；
- Gazebo 与 ROS 关系密切，二者同属机器人工程方向。

因此，ROS 与强化学习训练相对独立，可在涉及真机部署时再深入学习。

## 5. Sim2Real 与域随机化

在仿真中训练完成的策略部署到真实机器人时，常因仿真与现实的差异而性能下降，该差异称为 **Sim2Real Gap（仿真与现实的差距）**，主要来源包括：

- 真实环境的摩擦、电机延迟、传感器噪声等无法在仿真中完全复现；
- 仿真环境过于理想，策略可能学到仅在理想条件下有效的行为。

主流应对方法为**域随机化（Domain Randomization）**：在训练时随机改变仿真环境的参数，如地面摩擦、机器人质量、观测噪声，并施加随机外力扰动，使策略在各种条件下均能保持鲁棒，从而提升其在真实环境中的适应能力。

本项目 `velocity_env_cfg.py` 的 `EventCfg` 中实现了该思路，包括 `randomize_rigid_body_material`（随机摩擦）、`randomize_rigid_body_mass_base`（随机质量）、`randomize_push_robot`（随机外力扰动），以及观测项中添加的噪声（`noise`）等。

## 7. 推荐学习路径

建议按以下顺序循序渐进，结合实践学习：

1. **熟悉基础环境**：掌握 Linux 命令行、SSH 远程连接、Conda 环境激活与 Git 基本操作，按 `CLAUDE.md` 将本项目运行起来。

3. **学习强化学习概念**：通过入门课程（如 EasyRL、David Silver 课程）掌握第 3.2 节的基本要素与 PPO 的基本思想，无需深入数学推导。
4. **阅读项目配置**：精读 `velocity_env_cfg.py`，理解各观测项与奖励项的含义，这是从运行到调优的关键。
5. **动手实验**：修改某一奖励项或参数后重新训练，观察训练曲线与行为变化。

本知识体系横跨操作系统、深度学习、强化学习与机器人多个领域，初次学习时难以全部掌握，建议先完整运行项目，再逐步深入理解。
